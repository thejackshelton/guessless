# Guessless real-agent repository benchmark

## Objective

Run same-model coding agents directly on authentic maintenance work from Markless, Frameless, and Versionless, then decide from their tested patches and raw transcripts whether Guessless improves real agent outcomes.

## Original Request

`Give me goal to run, and MAKE SURE it's on BENCHMARKS WITH REAL AGENTS NO SPENDING TIME ON THE HARNESS OR SETUP OR WHATEVER GET RIGHT INTO IT LIKE YOUR LIFE DEPENDS ON IT`

## Goal Oracle

The oracle is a sealed paired benchmark of real coding agents working in isolated checkouts of real repositories on real historical maintenance tasks. Every cell must preserve its raw transcript, patch, test result, timing, token/tool accounting, and Guessless-use record. The result must support an explicit ship/pilot/do-not-ship decision without synthetic fixtures or harness claims.

## Goal Kind

`specific`

## Current Tranche

The informed v3 batch proved that explicit context changes Guessless selection from 0/5 to 5/5, but its final Judge returned INCONCLUSIVE because only two cells received bounded results, those results arrived after implementation, the context changed mid-batch, one pair was contaminated, and some sealed patches omitted untracked helper files. The owner then explicitly continued the goal. Run one final uniform v4 batch of six new authentic paired tasks—two each from Markless, Frameless, and Versionless—using twelve `gpt-5.6-sol` coding agents. Freeze one correctly delimited treatment card before launch; it says optional Guessless use must begin before edits if selected, supplies the exact symlink-free structural root, names the prepare-then-query workflow, and preserves `complete`/`partial`/`refused` honesty. Configure MCP approval correctly from cell one, capture tracked and untracked edits in every patch, and audit immediately. No harness or product engineering is part of this tranche.

## Non-Negotiable Constraints

- Benchmark actual same-model coding agents, not mocks, scripted responders, synthetic fixtures, or offline calibration.
- Use authentic JavaScript/TypeScript maintenance tasks from real Markless, Frameless, and Versionless Git history, with the solution commit hidden from agents.
- Agents implement the actual change in isolated worktrees and run relevant repository tests; read-only question answering does not count.
- Same base maintenance prompt, model, repository state, limits, and environment per pair. The declared treatment intervention is the current Guessless MCP plus the frozen onboarding context; control receives neither.
- The treatment context must name Guessless, explain when its structural analysis is useful, name the prepare-snapshot then impact/query workflow, and explain `complete`/`partial`/`refused` honesty. It must say use is optional and must not require, reward, or claim success from invocation alone.
- Launch the first live pair before selecting the remainder of the batch; task selection and worktree creation are strictly time-boxed mechanics, not a planning phase.
- Do not edit product code, evaluator code, package manifests, lockfiles, benchmark harnesses, fixtures, or old sealed evidence.
- Use direct Git, Codex, and repository test commands. Evidence capture is allowed; saved runner or setup code is not.
- No retries, substitutions, cherry-picking, or silent omissions. Seal every attempted cell honestly.
- Preserve fail-closed receipts and name every invalid, unresolved, or untested outcome.

## Stop Rule

Stop only after the uniform fixed v4 real-agent batch is sealed and a final Judge maps tested patch quality, completion, correctness, false completeness, time, tokens, tools, informed Guessless selection, pre-edit successful-result use, and semantic outcomes to an explicit ship/pilot/do-not-ship decision. Preserve v1-v3 as immutable history. Never convert an unavailable or unused tool into negative product evidence, and never detour into harness work.
