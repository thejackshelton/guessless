# Guessless must-have research

## Objective

Determine what would make Guessless a clear must-have for coding agents and sibling repositories, including whether semantic output must become more compact and which other product or architecture changes have the highest expected leverage.

## Original Request

Do research on what is going to make this a clear must have, do we need to make the semantic output more compact? Any other ideas? etc.

## Intake Summary

- Input shape: `specific`
- Audience: Guessless maintainer and sibling-project maintainers
- Authority: `requested`
- Proof type: `source_backed_answer`
- Completion proof: A durable, source-backed strategy report maps benchmark failures and current product behavior to a ranked roadmap and falsifiable experiments, and a final Judge confirms it answers what could make Guessless a must-have.
- Goal oracle: A skeptical evidence map showing why each recommendation should change accuracy, false completeness, latency, tokens, or tool calls, with measurable go/no-go thresholds.
- Likely misfire: Recommend compact output by intuition, optimize benchmark artifacts instead of real agent workflows, or produce a generic feature wishlist without causal hypotheses.
- Blind spots considered: Discovery/tool-selection friction, query granularity, result trust and proof, progressive disclosure, caching/indexing, task-specific value, product positioning, integration cost, benchmark representativeness, and the possibility that broad integration is the wrong wedge.
- Existing plan facts: V5 found positive reach value but rename regression, added false completeness, and material overhead; the new work is research, not permission to rerun or mutate sealed v3-v5 evidence.

## Goal Oracle

The oracle is a reviewed report that traces local evidence and primary sources into a prioritized must-have thesis, distinguishes compactness from other causes, and specifies experiments whose results would justify implementation and a future separately preregistered benchmark.

## Goal Kind

`specific`

## Current Tranche

Complete local and external research, choose the highest-leverage product thesis, publish the durable strategy and experiment roadmap, and finish only after a read-only audit proves the recommendations are evidence-backed and actionable.

## Non-Negotiable Constraints

- Preserve sealed v3, v4, and v5 evidence byte-for-byte; never retry or rescore them.
- Use primary sources for external technical claims.
- Separate observed evidence, inference, and hypothesis.
- Do not implement product changes during this research tranche.
- Do not optimize only for the synthetic benchmark; every proposal must explain the real agent workflow it improves.

## Stop Rule

Stop only when the final audit proves the report answers the full research question with ranked, falsifiable, source-backed recommendations.
